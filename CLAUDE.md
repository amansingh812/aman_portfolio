## 1. What this project is

A portfolio + lead-generation site for **BuildFirstSite**, a web/app development
studio serving **Australia (primary)** and the **USA (secondary)**.

The site's entire job is: **rank in Australian organic search → get a quote request.**
Every technical and content decision should be judged against that.

Positioning / differentiators to reinforce in all copy:

- **Fixed, transparent, upfront pricing in AUD** (landing pages from $600, business
  sites from $2,000, e-commerce from $4,000)
- **Modern stack** — Next.js, React, AI integrations (OpenAI / Gemini)
- **Fast delivery**, direct communication with the builder (no agency layers)
- **You own the code** — no platform lock-in, no forced monthly subscription

## 2. Stack & architecture

- **Next.js 15 App Router + TypeScript + React 19**
- **Tailwind CSS v4** via `@tailwindcss/postcss` (NOT the legacy `tailwindcss`
  PostCSS plugin)
- Deployed on **Vercel**. Framework preset = Next.js, **Output Directory must be
  blank** (`.next`). The repo still contains a stale `dist/` folder from the old
  Vite build — it is not the build output; do not point anything at it.
- Migrated from Vite + Express. Retired files live in `_vite-backup/` (gitignored).

### Two kinds of pages — know the difference

| Type | Location | Notes |
|---|---|---|
| **Legacy static SEO pages** (20 dirs) | `public/<slug>/index.html` | Hand-authored HTML. **These already rank on Google — do not rewrite or convert them to Next routes without an explicit instruction.** Edit the HTML in place. |
| **Next.js routes** | `app/**/page.tsx` | All new pages go here. Statically prerendered. |

Static pages are served at clean URLs via `beforeFiles` rewrites in
`next.config.mjs`, generated by `collectStaticIndexRoutes()` which recursively
scans `public/` for directories containing `index.html`. **Any new
`public/<slug>/index.html` is picked up automatically — no config edit needed.**

### Key files

```
app/layout.tsx              root metadata, viewport, 4 JSON-LD blocks,
                            flash-free dark-mode inline script
app/page.tsx                → renders app/home-client.tsx
app/home-client.tsx         the homepage ('use client')
app/globals.css             Tailwind v4 @theme + design tokens (light + html.dark)
app/components/SiteHeader.tsx   shared header w/ theme toggle
app/components/SiteFooter.tsx   shared footer — THE internal-link hub
app/components/ComparisonPage.tsx  shared renderer for all vs-pages
app/lib/case-studies.ts     data for /work/[slug]
app/lib/comparisons.ts      data for */-vs-custom-website
app/lib/guides.ts           data for /guides/[slug]
public/sitemap.xml          MUST be updated when adding any page
next.config.mjs             static-page rewrites (do not break this)
```

### Conventions (follow these — do not invent new patterns)

- Content lives in **typed data files in `app/lib/`**, rendered by a shared
  component. Adding a case study / comparison / guide = add an object to the
  array, nothing else.
- `trailingSlash: true` — **all internal links end in `/`** (`/work/hs-race-gear/`).
- Dynamic routes: `generateStaticParams()` + `export const dynamicParams = false`.
- Next 15: `params` is a **Promise** — `async function Page({ params }: { params: Promise<{slug: string}> })`.
- Env vars exposed to the browser need the `NEXT_PUBLIC_` prefix
  (`NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY` — must also be set in Vercel).
- Styling uses the CSS custom-property tokens in `globals.css`
  (`text-text-secondary`, `bg-bg-secondary`, `border-border-primary`, `.card`,
  `.display`, `.eyebrow`, `.btn-primary`). Don't hardcode hex colours.

### Sandbox caveat

`next build` times out on the mounted filesystem in the Cowork sandbox.
Verify with **`npx tsc --noEmit`** instead, and tell the user to run
`npm run build` locally before deploying. Never claim a build passed if only
type-checking ran.

**Where we win:** published fixed prices, modern stack, speed, code ownership,
direct access to the developer. Most competitors hide pricing behind "contact
us" — our transparency is the wedge. Lean on it.

**Where they beat us:** review volume/social proof, backlink profiles, published
case-study depth, blog cadence. Close those gaps, in that order.

### Content rules for every new page

1. One primary keyword + 2–3 supporting long-tails.
2. Unique `title` (keyword first, brand last) and `description` with a benefit + CTA.
3. One `<h1>` containing the primary keyword; keyword-relevant `<h2>`s.
4. **Schema** — always: `BreadcrumbList` + the right type
   (`Article` for guides, `CreativeWork` for case studies, `FAQPage` for Q&A,
   `LocalBusiness`/`ProfessionalService` for location pages, `HowTo` for process).
5. **AUD pricing stated explicitly** where relevant.
6. **Minimum 3 internal links out** + linked from `SiteFooter.tsx` (and the
   sitemap). No orphan pages, ever.
7. Descriptive `alt` on every image.
8. Dual CTA: "Get a free quote" → `/#contact` and "Book a free call".
9. Canonical set via `alternates: { canonical: '/path/' }`.
10. **Add the URL to `public/sitemap.xml` and bump `sitemap-index.xml` lastmod.**

## 5. Default workflow for "add a page"

Full procedure: **`docs/SEO-PLAYBOOK.md`** — follow it for any page add or
on-page optimisation. Short version:

1. Pick the target keyword; confirm no existing page owns it (cannibalisation check).
2. Add the entry to the relevant `app/lib/*.ts`, or create a new lib + shared
   renderer if it's a new page *type*.
3. Write `metadata` (title, description, keywords, canonical, openGraph).
4. Add schema blocks (`BreadcrumbList` + type-specific).
5. Add internal links **in and out**, including `SiteFooter.tsx`.
6. Update `public/sitemap.xml` + `sitemap-index.xml`.
7. `npx tsc --noEmit`, then tell the user to run `npm run build` locally.

## 6. Honesty rules for this repo

- Don't claim a page "will rank" — rankings take months and depend on links.
- Don't invent client names, testimonials, review counts, or metrics for case
  studies. Ask the user for real ones.
- Keyword volumes above are **estimates**, not measured data. Label them as such
  if they appear in anything client-facing.
- If only `tsc` ran, say so — don't imply the production build passed.
